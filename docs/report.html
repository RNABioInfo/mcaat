MCAAT: Cycle Finder — Algorithmic & Optimization Report ✅

Scope: This document describes only the algorithmic changes and optimizations introduced in the optimizations branch for the cycle finder logic, organized step-by-step.

Summary

  1. Replaced critical sections with per-thread buffers + serial merge.
  2. Introduced a lock-free atomic bitset as the visited structure.
  3. Reduced allocations by reusing per-thread pools (megahit-style).
  4. Applied traversal micro-optimizations (prefetch, fixed arrays, branch hints).

Step-by-step changes

  1. Per-thread buffers + serial merge
    • Replaced concurrent writes to shared containers with local_chunks[tid] and local_results[tid], then merged serially.
    • Files: ChunkStartNodes, FindApproximateCRISPRArrays.
  2. Lock-free visited bitmap
    • Introduced std::vector s_visited_words and helpers: InitializeVisitedGlobal, IsVisitedGlobal, MarkVisitedGlobal.
    • Atomic builtins (__atomic_load_n, __atomic_fetch_or) are used with relaxed ordering.
  3. Per-thread pools & fewer allocations
    • Added static thread_local pools for DLS stack and visited set; reuse capacity to avoid repeated alloc/free.
    • File: DepthLevelSearch.
  4. Traversal micro-optimizations
    • Fixed-size neighbor arrays, prefetch, branch hints, and small unrolling in hot loops.
  5. Serial result merging & memory hygiene
    • Per-thread maps are moved into the shared results in a serial loop; call malloc_trim(0) intermittently.

Expected impact

  • Better multithreaded scaling due to reduced contention and allocator pressure.
  • Reasonable memory usage (1 bit per node for visited bitset).

Limitations & future work

NUMA-aware allocation and deeper profiling are recommended next steps.

Quick validation

  1. Checkout optimizations, build, and run the same workload across several thread counts (1, 8, 24, 48, 128).
  2. Use perf and numastat to verify reduced contention and memory hotspots.

Files touched: src/cycle_finder.cpp (+ associated header updates).

TL;DR: per-thread buffers + lock-free visited bitmap + reused pools = less contention and better parallel throughput.
